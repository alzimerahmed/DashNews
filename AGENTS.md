# DashNews — Rules for AI Agents

## Project

DashNews = free and open-source feed reader for macOS and iOS (codebase forked from Ranchero Software's NetNewsWire, rebranded; repo: https://github.com/alzimerahmed/DashNews, owner: Alzimer Ahmed). Supports RSS, Atom, JSON Feed, and RSS-in-JSON. Local/on-device-first: articles are stored in a local SQLite database, sync is optional per account (CloudKit, NewsBlur, Feedbin-style providers), and there is no required account.

**License:** MIT, copyright © 2026 Alzimer Ahmed (upstream was MIT © Brent Simmons — attribution preserved in git history). Keep the MIT license text intact.

**Scope:** Native Apple-platform app only (macOS + iOS + widget + share/safari extensions). No Android, no web frontend. All verification is CI-only (see Build/Verify).

## How It Works (domain constraints — read before touching the engine)

- **Article pipeline**: feeds are fetched (`Modules/RSWeb`), parsed (`Modules/RSParser` — RSS/Atom/JSON Feed/OPML), stored (`Modules/ArticlesDatabase`, SQLite via `Modules/RSDatabase`), and rendered (`Shared/Article Rendering`, HTML templates + `Shared/ArticleStyles`).
- **Accounts are the data source of truth** (`Modules/Account`): `OnDisk` (local), `CloudKit`, `NewsBlur`, `Feedbin`, `Reader` (Google-Reader-compatible API). UI reads through the account layer — never bypass it to touch the database directly.
- **Tree navigation**: sidebar is a tree of folders/feeds (`Modules/RSTree`, `Shared/Tree`); smart feeds (Today, Starred, Unread) are computed (`Shared/SmartFeeds`).
- **Sync**: `Modules/SyncDatabase` + `Modules/CloudKitSync` handle incremental sync with status (unread/starred) reconciliation. Status changes must go through the account/sync layer, not raw SQL.
- **Feed parsing is strict** — see `Technotes/AvoidFeedParsing.markdown` before touching `RSParser`; malformed feeds are handled with heuristics that have long histories.
- **Main-thread discipline**: AppKit/App delegate callbacks assume the main thread; database work is async. Follow existing `MainActor`/`@MainActor` patterns.

## Tech Stack & Conventions (do not fight it)

### Language & Tooling
- **Language**: Swift (Xcode 26.3 toolchain on CI), SwiftUI for new UI, AppKit where the Mac app already uses it. No UIKit/SwiftUI rewrites of working screens without a decision record.
- **Project**: single `NetNewsWire.xcodeproj` (target/scheme rename to DashNews is planned — see `docs/plan.md`; until then use existing scheme names). Targets: macOS app, iOS app, iOS widget, iOS share extension, Mac share extension, Mac Safari extension.
- **Modules**: `Modules/` are local Swift packages (RSCore, RSDatabase, RSParser, RSWeb, RSTree, Account, Articles, ArticlesDatabase, CloudKitSync, FeedFinder, HTMLMetadata, Images, NewsBlur, Secrets, SyncDatabase, ActivityLog, ErrorLog). Keep module boundaries — app code imports modules, modules never import the app.
- **Lint**: SwiftLint, run with `--strict` in CI (`.swiftlint.yml`). Zero-warning policy (`buildscripts/fail_on_warnings.sh`).
- **Tests**: XCTest via test plans — `NetNewsWire-CI.xctestplan` (macOS), `NetNewsWire-iOS.xctestplan` (iOS). Pure-logic tests live in module `Tests/` dirs.

### Architecture & Conventions
- **Folders**: `iOS/` (iOS app), `Mac/` (Mac app), `Shared/` (cross-platform app code), `Modules/` (packages), `Widget/`, `Resources/` (themes, article styles), `Technotes/` (internal engineering docs — read them, they are the real docs).
- **Style**: follow `Technotes/CodingGuidelines.md` and `.swiftlint.yml`. Naming follows existing patterns (`RS*` prefixes belong to module libraries).
- **Localizable strings**: `Shared/Resources/Localizable.xcstrings` and per-platform `.xcstrings` catalogs — user-facing strings go there, never hardcoded.
- **Secrets**: sync API credentials are compile-time generated by `buildscripts/updateSecrets.sh` from repo secrets (CI) — never commit real keys; `Modules/Secrets` sources are generated, do not hand-edit.

## Build / Verify

```bash
# CI (GitHub Actions, .github/workflows/ci.yml — push/PR to main):
#   1. SwiftLint --strict
#   2. macOS tests:  xcodebuild -project NetNewsWire.xcodeproj -scheme NetNewsWire -testPlan NetNewsWire-CI -destination "platform=macOS,arch=arm64"
#   3. iOS tests:    xcodebuild -project NetNewsWire.xcodeproj -scheme NetNewsWire-iOS -testPlan NetNewsWire-iOS -destination "platform=iOS Simulator,name=iPhone 17"
```

**Remote-first verification (mandatory):** we do NOT build or test locally — this workspace is Windows and all builds/tests run in GitHub Actions (macOS runners). Local work is edit-only: static review while iterating. Push a branch and let CI verify; a CI green check counts as the gate.

**Release flow:** App Store/TestFlight releases are driven by dedicated CI workflows; version bumps and release steps are documented in `Technotes/HowToDoiOSAppStoreRelease.markdown`, `Technotes/HowToDoiOSTestFlightRelease.markdown`, and `Technotes/HowToDoMacSparkleRelease.markdown`. Do not tag releases without updating those steps.

## Gotchas

- **Windows checkout**: `AppStore/` screenshots contain a filename with `"` (invalid on Windows). The local clone uses sparse-checkout to exclude `AppStore/`; do not re-add those paths or remove the sparse-checkout config.
- **CI checks out submodules** (`submodules: recursive`) — new submodules must be added to the workflow or CI builds break.
- **Secrets sources must exist before building** — CI runs `buildscripts/updateSecrets.sh` first; local Xcode builds fail without it (moot here — CI-only).
- **Signing**: `setup.sh` / `DeveloperSettings.xcconfig` handle signing locally; CI uses `xcconfig/no-signing` overrides. Never hardcode team IDs.
- **R8-equivalent caution**: there is no local build to catch resource/reference mistakes — grep all references (storyboards, `.xcstrings` keys, asset names) before deleting anything.
- **Don't break the on-device promise**: no analytics, no tracking, no required account. Network access is feeds/sync only.
- **Feed parsing heuristics are load-bearing** — changes to `RSParser` need tests with real-world malformed feed fixtures.

## Agent Guidelines & Constraints

### Do's
- **Write tests** for new module behavior (XCTest, behavior not implementation).
- **Conventional Commits**: `type(scope): description`.
- **Read the Technotes** before working in a domain — they encode years of upstream decisions.
- **Respect module boundaries** — new reusable logic goes into the right `Modules/` package, not the app target.
- **Plan discipline** — `docs/plan.md` must contain a Quality Gate (security/perf/a11y/anti-vibe audits) and a Release phase. Every `idea.md` Feature Gap entry maps to a phase or is explicitly deferred. When a phase answers an open question in `docs/research.md`, close it there in the same change.

### Don'ts
- **NO local builds or test runs** — verification is CI-only (user directive; Windows host has no Xcode).
- **NO secrets in code** — sync credentials via CI-generated secrets only.
- **NO new heavy dependencies** without a decision record in `docs/research.md` (license must stay MIT-compatible).
- **NO deleting resources** without grepping all reference types (plists, xcconfigs, `.xcstrings`, asset catalogs, storyboards).
- **NO renaming targets/schemes/bundle IDs ad hoc** — that is a planned, CI-verified phase (see `docs/plan.md`).

## Agent Guidelines & Workflow (this repo's .devin system)

### Resource Discipline (mandatory, non-trivial tasks)
Before any non-trivial task:
1. Read `docs/toolset.md` intent-map (task type → resources)
2. Invoke every skill + sub-agent in that row
3. Read every rule for that task type (`.devin/rules/`)
4. At task end: `code-reviewer` sub-agent on final diff (non-negotiable)
5. Append learnings via `/ce-compound` if durable lesson

Phase implementations (task completes a docs/plan.md row): follow `.devin/prompt/phase.md`.

Skip all this for single-line edits, pure Q&A, reading files.

### Project-Type Filter (Apple-platform feed reader)
Per `docs/toolset.md` intent-map:
- **Skip web-only/non-Apple:** pwa-engineer, seo-specialist, css-architect, playwright-design-clone, payment-integrator, email-engineer, monorepo-manager, web-scraper, search-optimization, backend-architect (no server).
- **Keep universal:** code-reviewer, debugger, test-engineer, security-auditor, performance-engineer, git-master, migration-specialist, docs-writer, build-optimizer, caveman-compressor, vibe-coding-auditor, type-safety-engineer, state-manager, database-engineer (SQLite/sync durability), i18n-specialist (xcstrings/RTL), media-optimizer, animation-engineer, frontend-designer (SwiftUI taste), content-writer, accessibility.
- **Quality gates:** CI-only — SwiftLint + macOS/iOS test plans on GitHub Actions. No local builds.
